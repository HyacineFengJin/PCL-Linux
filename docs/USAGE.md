# 使用指南

PCL Linux 支持下载安装 Minecraft 原版，也可以启动已有的游戏版本。首次运行前，请按[README](../README.md#构建与运行)完成构建。

## 选择游戏目录

1. 打开「启动 → 实例选择」。
2. 点击「添加已有文件夹」，通过系统文件夹选择器选择已有的 `.minecraft` 目录，或一个已创建的空目录用于安装原版。
3. 在左侧文件夹列表中切换目录，选择要运行的实例。可以输入实例名称进行搜索。

每个目录分别记住所选实例和实例内存设置。通过文件夹右侧的菜单可改显示名称、调整顺序或移除登记；这些操作不会改名或删除磁盘上的游戏文件。临时断开或不可读的目录仍保留在列表中，恢复访问后可重新选择。个别损坏的实例会单独显示提示，其他实例仍可使用。

文件夹选择器使用 XDG Desktop Portal。系统需要运行 `xdg-desktop-portal` 及适合桌面环境的文件选择器后端。取消选择不会添加目录；选择器不可用时会显示提示。

如果没有显示实例，请检查所选目录中是否有 `versions` 文件夹。

## 安装游戏与加载器

1. 先在「启动 → 实例选择」中选择目标游戏目录。
2. 打开「下载」，展开正式版、预览版、远古版或愚人节版分组。
3. 选择版本，在顶部填写实例名称。需要模组加载器时，展开 Fabric、Forge 或 NeoForge 并选择版本；三个加载器只能选择一个。未手动改名时，选择组件会自动补充实例名称；手动填写的名称会保留。
4. 点击「开始下载」。启动器会从官方源获取游戏本体、依赖库、资源及 Linux 原生库，并校验下载文件。加载器的启动配置与必要文件会一起安装。
5. 完成后，实例会加入开始下载时所选的目录，并成为该目录的所选实例。切回该目录后，返回「启动」开始游戏。

「任务管理」显示原版信息、支持库、资源文件和所选组件的下载与安装步骤，以及总进度、下载速度和剩余文件。悬停在任务名称上可查看安装目录。

点击任务右上角的取消按钮后，启动器停止下载和组件处理，清理未完成文件，并返回下载版本列表。清理过程中按钮会禁用；若任务已经完成，保留完成结果。已校验通过的完整公共资源与依赖库可在重试时复用。安装任务进行时可切换目录浏览，目标目录保持不变；等待任务结束后才能启动游戏或开始另一个安装。正在安装或运行游戏的目录不能移除登记。

已有的同名实例不会被覆盖。已安装的 Minecraft 版本仍可选择，使用不同实例名称可另装一份。部分早期版本暂不支持自动安装，界面会显示原因。OptiFine、LabyMod 自动安装尚未开放。

Forge、NeoForge 自动安装支持现代官方安装器格式；旧版 Forge 安装器格式暂不支持，会保留已有实例并清理本次临时文件。

安装结果会显示所需 Java 主版本；游戏文件下载不包含 Java。请先确保系统或项目中有对应 Java。Forge、NeoForge 安装时还需要对应的 Java 主版本执行组件处理，启动器会自动查找。

## 浏览安装包与社区资源

「下载 → 安装包」可浏览 Minecraft、OptiFine、Forge、NeoForge、Cleanroom、Fabric、Legacy Fabric 和 LiteLoader 的官方版本目录。点击版本分组展开列表，点击「打开官网」访问对应项目；LabyMod 的安装器通过官网提供。此处的单文件与安装器下载尚未开放；安装 Fabric、Forge、NeoForge 请从 Minecraft 版本选择页进入自动安装。

「下载 → 社区资源」可搜索 Modrinth 的模组、整合包、数据包、资源包和光影包。点击资源查看版本详情，并按游戏版本、加载器筛选；版本分组内可浏览必要与可选依赖。选择整合包版本可查看实例名称表单。资源下载安装、CurseForge、世界目录和收藏管理尚未开放。

## 实例界面

「实例设置 → 修改」显示当前 Minecraft 和加载器版本；「导出」提供名称、版本、文件选择与高级选项表单。实际修改、重置和导出尚未开放。

本地资源列表支持搜索、排序、多选与详情查看。资源更新检查与在线下载尚未开放。

## 调整实例显示

打开「实例设置 → 概览」，在「个性化」中操作：

- 点击「修改实例描述」，输入描述并确认；支持多行，留空可清除。
- 选择内置图标或「自动」，选择实例列表的分类或「自动」。选择后即时保存。「自动」按检测到的加载器显示图标和分组。
- 点击「加入收藏夹」。收藏的实例在「实例选择」的收藏夹分组中置顶；点击「移出收藏夹」恢复普通分组。

实例列表会显示描述，搜索支持实例名和描述。分类控制列表分组，Minecraft 与加载器版本继续显示实际检测结果。

这些资料按登记的游戏目录和实例分别保存，关闭并重新打开启动器后仍保留。不同目录中的同名实例各自管理。实例物理改名与删除尚未开放。

若保存时提示资料已经变化，点击「重新读取」查看最新资料，再重新编辑。游戏或文件任务进行时，需等待结束后保存实例信息。

## 管理本地资源

打开所选实例的「模组」「资源包」或「光影包」页面。先退出游戏，并等待安装或其他文件操作完成。

- **启用／禁用模组**：悬停在模组行上点击对应按钮；也可选择多个模组，使用顶部批量按钮。禁用会将 `.jar` 改为 `.jar.disabled`，启用会改回 `.jar`。
- **导入**：点击「从文件安装」，通过系统文件选择器多选文件。模组支持 `.jar` 和 `.jar.disabled`，资源包与光影包支持 `.zip`。文件复制到该实例实际使用的资源目录，源文件保留。已有同名文件不会被覆盖，文件类型与归档格式会先检查。
- **删除**：选择文件并点击「删除」，核对确认框中的文件列表。删除的文件会保留用于恢复；点击「撤销删除」恢复最近一次删除，关闭并重新打开启动器后仍可使用。

若删除或恢复过程中发生冲突，先处理同名文件，再重新操作；启动器不会覆盖冲突文件。文件在选择后被外部程序修改时，需刷新列表后重新选择。标为「只读」的目录、符号链接或其他文件类型不能通过这些按钮修改。世界与服务器列表暂时仅供浏览。

资源位置遵循实例已有的目录隔离设置。多个实例共用资源目录时，启禁、导入和删除会影响使用该目录的其他实例。

当前删除需要资源目录与游戏目录位于同一文件系统；资源目录单独挂载时，操作可能被拒绝并回滚。

如果上一次资源操作未完成，页面会提供「恢复未完成操作」。恢复会尝试回到操作前的状态；遇到外部修改或同名冲突时会保留文件并显示原因。请先完成恢复，再启动游戏。

## 启动游戏

填写离线玩家名称，选好版本后点击「启动游戏」。启动器会先检查 Java 和依赖，再运行游戏。

离线身份适用于单人游戏和允许离线身份的服务器。[Microsoft 正版登录](AUTHENTICATION.md)暂未开放。

Java 会根据游戏要求自动选择。使用系统安装的 Java 时，确保所需版本可通过 `PATH`、`JAVA_HOME` 或 `/usr/lib/jvm` 找到。Forge / NeoForge 实例需要匹配对应的 Java 主版本。

## 调整内存

- 在「设置 → 启动」的内存卡片中设置默认上限，点击「保存设置」。
- 在「实例设置 → 设置」的内存卡片中设置单个实例的上限，点击「保存」。该值会覆盖默认设置。

界面以 GiB 为单位。最大内存是 Java 堆的上限，不代表游戏启动时会立即占用全部额度。

## 启动遇到问题

打开「实例设置 → 概览」查看实例信息；「设置 → Java」可查看检测到的 Java。启动失败时，可点击启动页的错误提示，或通过「设置 → 查看日志」查看输出。

已有实例缺少依赖时，当前版本仍需先补全原安装；下载页不会覆盖已有实例进行修复。已有的 Windows 游戏目录也可能需要对应的 Linux 原生库。

在游戏内使用正常退出操作。启动器中的「结束进程」会立即结束游戏，未保存的进度可能丢失。

## 桌面应用入口

在项目目录运行：

```sh
./install-desktop.sh
```

之后可以从系统应用菜单打开「PCL Linux（实验版）」。入口引用项目内的程序，移动项目目录后需要重新安装入口。

移除入口：

```sh
./uninstall-desktop.sh
```

此操作只移除应用菜单入口，保留程序和游戏文件。
