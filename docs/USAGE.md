# 使用指南

PCL Linux 支持下载安装 Minecraft 原版，也可以启动已有的游戏版本。首次运行前，请按[README](../README.md#构建与运行)完成构建。

## 选择游戏目录

1. 打开「启动 → 实例选择」。
2. 点击「添加已有文件夹」，通过系统文件夹选择器选择已有的 `.minecraft` 目录，或一个已创建的空目录用于安装原版。
3. 在左侧文件夹列表中切换目录，选择要运行的实例。可以输入实例名称进行搜索。

每个目录分别记住所选实例、内存和 Java 覆盖设置。通过文件夹右侧的菜单可改显示名称、调整顺序或移除登记；这些操作不会改名或删除磁盘上的游戏文件。临时断开或不可读的目录仍保留在列表中，恢复访问后可重新选择。个别损坏的实例会单独显示提示，其他实例仍可使用。

文件夹选择器使用 XDG Desktop Portal。系统需要运行 `xdg-desktop-portal` 及适合桌面环境的文件选择器后端。取消选择不会添加目录；选择器不可用时会显示提示。

如果没有显示实例，请检查所选目录中是否有 `versions` 文件夹。

## 安装游戏与加载器

1. 先在「启动 → 实例选择」中选择目标游戏目录。
2. 打开「下载」，展开正式版、预览版、远古版或愚人节版分组。
3. 选择版本，在顶部填写实例名称。需要模组加载器时，展开 Fabric、Forge 或 NeoForge 并选择版本；三个加载器只能选择一个。未手动改名时，选择组件会自动补充实例名称；手动填写的名称会保留。
4. 点击「开始下载」。启动器会从官方源获取游戏本体、依赖库、资源及 Linux 原生库，并校验下载文件。加载器的启动配置与必要文件会一起安装。
5. 完成后，实例会加入开始下载时所选的目录，并成为该目录的所选实例。切回该目录后，返回「启动」开始游戏。

「任务管理」显示原版信息、支持库、资源文件和所选组件的下载与安装步骤，以及总进度、下载速度和剩余文件。悬停在任务名称上可查看安装目录。

点击任务右上角的取消按钮后，启动器停止下载和组件处理，清理未完成文件，并返回下载版本列表。清理过程中按钮会禁用；若任务已经完成，保留完成结果。已校验通过的完整公共资源与依赖库可在重试时复用。安装任务进行时可切换目录浏览，目标目录保持不变；等待任务结束后才能启动游戏或开始另一个安装。正在安装或运行游戏的目录不能移除登记。

已有的同名实例不会被覆盖。已安装的 Minecraft 版本仍可选择，使用不同实例名称可另装一份。部分早期版本暂不支持自动安装，界面会显示原因。OptiFine、LabyMod 自动安装尚未开放。

Forge、NeoForge 自动安装支持现代官方安装器格式；旧版 Forge 安装器格式暂不支持，会保留已有实例并清理本次临时文件。

安装结果会显示所需 Java 主版本；游戏文件下载不包含 Java。请先确保系统或项目中有对应 Java。Forge、NeoForge 安装时还需要对应的 Java 主版本执行组件处理，启动器会自动查找。

## 浏览安装包与社区资源

「下载 → 安装包」可浏览 Minecraft、OptiFine、Forge、NeoForge、Cleanroom、Fabric、Legacy Fabric 和 LiteLoader 的官方版本目录。点击版本分组展开列表，点击「打开官网」访问对应项目；LabyMod 的安装器通过官网提供。此处的单文件与安装器下载尚未开放；安装 Fabric、Forge、NeoForge 请从 Minecraft 版本选择页进入自动安装。

「下载 → 社区资源」可搜索 Modrinth 的模组、整合包、数据包、资源包和光影包。点击资源查看版本详情，并按游戏版本、加载器筛选；版本分组内可浏览必要与可选依赖。模组、资源包和光影可安装到当前所选实例，见下节。选择整合包版本可查看实例名称表单；在线整合包/数据包安装、CurseForge、世界目录和收藏管理尚未开放。

## 安装 Modrinth 资源

1. 在「启动 → 实例选择」选择目标目录和实例，退出游戏并等待其他文件任务结束。
2. 打开「下载 → 社区资源」的模组、资源包或光影包，搜索并打开项目详情。
3. 选择与目标 Minecraft 和加载器兼容的版本。在所选版本的文件列表中选择文件，点击「安装到实例」。多文件版本默认选择主文件，也可选择其他运行用文件。
4. 核对目标实例、必要前置、复用文件、下载大小和提示，点击「开始安装」。任务管理显示信息检查、下载校验和文件提交。
5. 完成后，在目标实例的模组、资源包或光影列表中检查文件。资源包和光影仍需在游戏内启用；安装光影包不会自动安装光影引擎。

启动器重新读取官方项目、版本和文件数据，按声明的 SHA-512 与大小校验全部文件后统一提交。必要依赖会加入方案；可选依赖不会自动安装。无法解析的外部必要依赖、依赖循环、多版本冲突和不兼容资源会阻止安装，并显示原因。未知来源的本地文件不能完整参与项目冲突检查，方案会给出提示。

相同内容的已启用文件可复用。已禁用的相同模组不会自动启用；已有旧版本、同名不同内容或其他目标冲突也不会被覆盖，请先自行处理。当前不提供自动更新或替换旧文件。资源位置遵循原实例的隔离规则，共享资源目录中的变更会影响使用该目录的其他实例。

取消会停止请求并清理本次未完成文件，任务结束后返回原页面；进入提交阶段后不能再取消。中断提交或清理失败时，在所在游戏目录点击「恢复资源安装」，完成恢复后再操作或启动。遇到外部修改会保留内容并显示原因；不会通过覆盖冲突文件来完成恢复。文件操作需要支持匿名暂存的文件系统和 Linux 5.6 以上的目录校验能力，符号链接或单独挂载的目标目录可能被拒绝。

「下载文件」的单文件另存功能尚未开放；「安装到实例」会写入已选实例的资源目录。

## 实例界面

「实例设置 → 修改」可重置支持的实例组件；「导出」可选择内容生成本地 ZIP。操作前需退出游戏，并等待其他文件任务完成。

本地资源列表支持搜索、排序、多选与详情查看。在线资源安装从社区资源详情进入；本地资源更新检查尚未开放。

## 重置实例组件

1. 打开「实例设置 → 修改」，点击已选加载器旁的叉号移除当前选择，再选择 Fabric、Forge 或 NeoForge 的兼容版本。全部移除则重置为原版。
2. 点击「开始重置」，核对当前组件和新方案，再确认。Minecraft 版本保持当前版本；Minecraft 版本修改暂未开放。
3. 在「任务管理」查看安装和核心替换步骤。重置保留实例名称、模组、配置、存档和其他游戏内容，核心 JSON/JAR 的原始备份保留在游戏目录内。

目前支持具有独立核心文件的原版、Fabric 和现代 Forge/NeoForge 实例。继承版本、被其他实例复用的核心、旧版或自定义启动布局会显示不能重置的原因。核心暂存需要文件系统支持 `O_TMPFILE`；支持库单独挂载在其他文件系统时，重置可能被拒绝，原核心文件会保留。

取消会清理本次暂存文件并保留原实例。若上次重置中途关闭，页面会提示「恢复实例重置」；恢复完成后再启动游戏。遇到外部修改或冲突时保留备份并显示原因。更换加载器后，现有模组仍需与所选加载器兼容。

## 导出本地 ZIP

1. 打开「实例设置 → 导出」，填写整合包名称和版本。
2. 勾选内容。资源包、光影包、截图和存档可以逐项取消选择；默认不勾选存档、截图和服务器列表。
3. 点击「开始导出」，核对文件数量、大小及提示，再通过系统保存窗口选择 ZIP 位置。使用新的文件名，并保存到游戏目录之外。

ZIP 包含游戏版本核心文件、所选游戏内容和整合包信息。高级选项「打包资源文件」还会加入本地资源和支持库；支持库可能包含同目录其他实例的依赖，其他平台的原生库仍可能需要下载。缺少所需文件时会显示原因。导出不修改原文件，取消会清理未完成 ZIP。打包期间源文件变化时，请重新检查后导出。

「保存配置」保存此实例的导出选择，「读取配置」恢复已保存的选择。模组个人信息按已知文件位置区分，自定义位置请在分享前检查。Modrinth 上传模式、打包启动器和第三方整合包导入尚未开放；本地 ZIP 可用解压工具查看，也可按下节导入。

## 导入本地 ZIP

1. 在「启动 → 实例选择」选择目标游戏目录，点击左侧「导入整合包」。
2. 通过系统文件选择器选择本启动器导出的 ZIP；取消选择不会创建任务。
3. 填写新的实例名称，点击「确定」，核对文件数量、大小、复用文件与提示，再点击「开始导入」。
4. 在「任务管理」查看解压、校验和提交。完成后，切回目标目录选择新实例。

目前支持含 `pcl-export.json` 的本启动器本地 ZIP 格式；mrpack、CurseForge 和其他启动器格式暂不支持。导入将游戏内容放入新实例的独立目录，合并归档中的版本继承配置，并按新名称生成核心 JSON/JAR。归档原文件保持原样，不导入启动器账号或设置。

已有实例和不同内容的公共文件不会被覆盖。完全相同的公共支持库、资源文件可以复用。未打包的依赖可能仍需补齐；确认页面会给出提示，请勿将导入完成视为依赖已下载。若需要离线使用，请在源实例导出时勾选「打包资源文件」，并检查导出提示。

修改实例名称或目标文件后，需重新检查方案。已删除但尚未恢复的实例名称，以及仍有旧实例设置、资料或资源操作记录的名称不能用于新导入。取消将清理本次未完成文件；清理失败或中断会显示「恢复 ZIP 导入」，恢复后再启动游戏或继续写入。

## 删除与恢复实例

1. 退出游戏，等待其他文件任务结束，在「实例设置 → 概览 → 高级管理」点击「删除实例」。
2. 核对实例名称、文件数量与大小后确认。整个实例文件夹会移入该游戏目录的可恢复区域，实例目录内的存档、模组和配置会一起保留；公共库、素材和共享游戏内容保持原位置。
3. 在「实例选择」的恢复记录中点击「撤销删除」，恢复原目录。关闭并重新打开启动器后，记录仍可使用。

实例描述、收藏、导出配置、内存与 Java 覆盖设置保留，恢复后继续使用。原名称在恢复前保留，不能再安装或改名为同名实例。请先恢复该目录内的已删除实例，再移除游戏目录登记；目录暂不可访问时，需要先恢复目录访问。若其他程序占用原位置，请先移开冲突目录，再刷新恢复记录；启动器不会覆盖它。恢复副本被修改时会保留文件并显示原因。

被其他实例继承或复用 JAR 的实例暂不能删除。位于实例内部且仍被选择或登记为可用运行环境的 Java 也需先移到实例之外并重新添加。符号链接、挂载点、读取失败或文件变化会阻止删除。

准备阶段可以取消；开始移动目录时取消按钮禁用。未完成的删除或恢复会显示「恢复实例删除操作」，请先完成恢复。当前不提供永久清空恢复区的按钮。

## 调整实例显示

打开「实例设置 → 概览」，在「个性化」中操作：

- 点击「修改实例描述」，输入描述并确认；支持多行，留空可清除。
- 选择内置图标或「自动」，选择实例列表的分类或「自动」。选择后即时保存。「自动」按检测到的加载器显示图标和分组。
- 点击「加入收藏夹」。收藏的实例在「实例选择」的收藏夹分组中置顶；点击「移出收藏夹」恢复普通分组。

实例列表会显示描述，搜索支持实例名和描述。分类控制列表分组，Minecraft 与加载器版本继续显示实际检测结果。

这些资料按登记的游戏目录和实例分别保存，关闭并重新打开启动器后仍保留。不同目录中的同名实例各自管理。

若保存时提示资料已经变化，点击「重新读取」查看最新资料，再重新编辑。游戏或文件任务进行时，需等待结束后保存实例信息。

## 修改实例名称

1. 退出游戏，等待当前文件任务结束，打开「实例设置 → 概览」。
2. 在「个性化」中点击「修改实例名」，输入新名称，再点击「检查改名」。
3. 核对旧名、新名及需要同步的引用实例，点击「确定改名」。完成后，返回概览查看新名称。

此操作会重命名物理实例文件夹和同名核心文件，并同步其他版本的继承与 JAR 引用。Minecraft 版本、存档、模组和配置保持原内容；启动器中的实例内存、收藏、描述、导出配置和资源删除记录会跟随新名称。

同名目标、已有目标资料、版本 JSON 中无法识别的自定义路径引用，以及实例内容中的符号链接或挂载点会显示原因并拒绝改名。请先处理这些问题，或使用其他名称。检查后文件变化时，需要重新检查。此功能需要支持 `openat2` 的 Linux 内核，以及支持 `O_TMPFILE` 的游戏目录文件系统。

准备阶段可以取消，取消完成后保留原实例；开始提交文件时取消按钮禁用。若出现中断，页面提供「恢复实例重命名」：未提交完成的文件恢复旧名，已提交的文件继续完成资料同步。原始核心备份保留在游戏目录内。待恢复目录暂时离线时，请先恢复目录访问。恢复完成前，保存设置、切换目录和文件操作会暂停；外部修改造成的冲突会保留文件并显示原因。

## 管理本地资源

打开所选实例的「模组」「资源包」或「光影包」页面。先退出游戏，并等待安装或其他文件操作完成。

- **启用／禁用模组**：悬停在模组行上点击对应按钮；也可选择多个模组，使用顶部批量按钮。禁用会将 `.jar` 改为 `.jar.disabled`，启用会改回 `.jar`。
- **导入**：点击「从文件安装」，通过系统文件选择器多选文件。模组支持 `.jar` 和 `.jar.disabled`，资源包与光影包支持 `.zip`。文件复制到该实例实际使用的资源目录，源文件保留。已有同名文件不会被覆盖，文件类型与归档格式会先检查。
- **删除**：选择文件并点击「删除」，核对确认框中的文件列表。删除的文件会保留用于恢复；点击「撤销删除」恢复最近一次删除，关闭并重新打开启动器后仍可使用。

若删除或恢复过程中发生冲突，先处理同名文件，再重新操作；启动器不会覆盖冲突文件。文件在选择后被外部程序修改时，需刷新列表后重新选择。标为「只读」的目录、符号链接或其他文件类型不能通过这些按钮修改。世界与服务器列表暂时仅供浏览。

资源位置遵循实例已有的目录隔离设置。多个实例共用资源目录时，启禁、导入和删除会影响使用该目录的其他实例。

当前删除需要资源目录与游戏目录位于同一文件系统；资源目录单独挂载时，操作可能被拒绝并回滚。

如果上一次资源操作未完成，页面会提供「恢复未完成操作」。恢复会尝试回到操作前的状态；遇到外部修改或同名冲突时会保留文件并显示原因。请先完成恢复，再启动游戏。

## 启动游戏

填写离线玩家名称，选好版本后点击「启动游戏」。启动器会先检查 Java 和依赖，再运行游戏。

离线身份适用于单人游戏和允许离线身份的服务器。[Microsoft 正版登录](AUTHENTICATION.md)暂未开放。

Java 默认按游戏要求自动选择，也可指定全局或实例 Java，见下节。Forge / NeoForge 实例需要匹配对应的 Java 主版本。

## 选择 Java

1. 打开「设置 → Java」，等待检测完成。列表显示本机可用运行环境的版本、架构、供应商和可执行文件路径。
2. 点击「自动选择」或一个 Java 条目，即时保存全局选择。自动模式优先使用满足要求的最低主版本。
3. 要添加其他安装位置，点击「添加」，通过系统文件选择器选择 Linux Java 安装中的 `bin/java` 可执行文件。检查通过后加入列表，再点击该条目选用。取消选择不会更改设置。

在「实例设置 → 设置」的「游戏 Java」中，可选择「跟随全局设置」、「自动选择」或一个指定的 Java，即时保存。实例单独选择自动时，会使用自动匹配；相同名称的实例在不同游戏目录中分别保存选择。

自动发现会检查项目及游戏目录的运行环境、`PATH`、`JAVA_HOME` 和 `/usr/lib/jvm`。添加 Java 仅登记已有安装，当前不提供 Java 下载。加载器安装和组件重置仍会自动寻找处理器所需的 Java；游戏 Java 选择用于检查和启动游戏。

启动前会重新检查所选程序。手动路径失效、没有执行权限、架构不符或主版本不兼容时，启动失败并显示原因；设置会保留，可重新添加 Java 或改为自动。Forge / NeoForge 需要相同主版本，其他实例使用满足所需主版本的 Java。游戏运行或文件任务进行时，Java 选择暂不可修改。

旧设置升级前会保存备份。如果存在未完成的实例改名，请先完成恢复。手动登记的 Java 位于待改名实例内部时，需要先移到实例之外并重新添加，才能改名。

## 调整内存

- 在「设置 → 启动」的内存卡片中设置默认上限，点击「保存设置」。
- 在「实例设置 → 设置」的内存卡片中设置单个实例的上限，点击「保存」。该值会覆盖默认设置。

界面以 GiB 为单位。最大内存是 Java 堆的上限，不代表游戏启动时会立即占用全部额度。

## 启动遇到问题

打开「实例设置 → 概览」查看实例信息；「设置 → Java」可检查运行环境与当前选择。启动失败时，可点击启动页的错误提示，或通过「设置 → 查看日志」查看输出。

已有实例缺少依赖时，当前版本仍需先补全原安装；下载页不会覆盖已有实例进行修复。已有的 Windows 游戏目录也可能需要对应的 Linux 原生库。

在游戏内使用正常退出操作。启动器中的「结束进程」会立即结束游戏，未保存的进度可能丢失。

## 桌面应用入口

在项目目录运行：

```sh
./install-desktop.sh
```

之后可以从系统应用菜单打开「PCL Linux（实验版）」。入口引用项目内的程序，移动项目目录后需要重新安装入口。

移除入口：

```sh
./uninstall-desktop.sh
```

此操作只移除应用菜单入口，保留程序和游戏文件。
