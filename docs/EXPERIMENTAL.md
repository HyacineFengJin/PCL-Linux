# 实验功能

在 **工具** 的侧栏分别打开 **插件管理、模组制作、一键搬运**。共享 Pi 配置位于独立的 **AI 管理** 页面。它们目前均为 **Experimental / 实验性**，使用启动器现有的卡片、下拉框和确认弹窗。

插件系统分为「插件管理」和「插件市场」；市场当前仅为留白页面，尚未开放。

## 插件系统 · 0.6.2

导入 JSON 声明或 `.pclext` JSON 包，检查名称、发布者及请求权限，再选择授权并安装。发布者身份未经验证。

支持的权限：

- 显示带来源标识的纯文本功能卡片。
- 切换到启动、实例选择、下载、工具或设置页面。
- 展示当前实例的游戏版本、加载器、模组数量和隔离状态。

可以撤销权限、禁用插件、重新授权，或用安全模式暂停全部卡片。声明和授权保存在本地；更新声明内容需要再次确认。撤销必需权限会暂停插件，撤销可选权限会停用相应按钮。

关闭审核弹窗会取消尚未提交的授权；迟到的审核结果不会重新打开弹窗。切页或切换连接后，旧卡片的导航、实例摘要和确认回调会退役。已经提交给宿主的安装或权限修改仍由宿主完成，再次打开页面可刷新查看结果；失败的确认需要重新审核。

这是数据型插件系统，不执行插件代码。实例摘要不包含目录、账号或登录令牌。示例声明见 [Instance Compass](../experimental/extensions/examples/instance-compass.json)。

同一导入入口可选择 PCL N 或 Nex 插件的 **`plugin.json`**，或受支持的 **`.pnp` / `.pclx` 包**，打开只读兼容报告，查看声明的程序集入口、服务、权限、插件依赖及 Mixin 配置。包检查只读取目录、ZIP 头和固定 JSON 元数据，不提取到安装目录；程序集、Mixin、签名及公钥数据流不会被读取。报告没有安装授权，不执行插件代码，不验证发布者、签名、其他载荷内容或完整上游兼容性。

包须包含根部唯一的 `plugin.json`，不超过 32 MiB、128 个条目；每份 JSON 最多展开 64 KiB。仅支持单卷 ZIP32 的 Stored/Deflate 子集；拒绝链接、危险或重复路径、加密、ZIP64、额外字段、包尾注释、未知格式版本及容量/压缩比超限。N 包的包、签名、文件表和清单版本仅支持 1；Nex 不支持旧脚本入口和显式版本化封装。其余边界和固定官方格式依据见 [包清单检查范围](../experimental/extensions/compat/PACKAGES.md)。报告里的 SHA-256 标识清单，不能用作整个包的完整性或签名结论。

N 的 Avalonia/DirectInject 页面以及 Nex 的 PCL.Core/Mixin 环境尚未适配；这些外部插件仍不能安装或运行。

提供独立的 [开发验证工具](../experimental/extensions/compat/README.md)：用 N SDK 0.2.5 原始 Hello 源码验证命令及双语设置页描述接口，另用 RH 自写夹具验证通知服务到纯文本卡片模型的映射。该工具不随启动器启动；通知卡片尚未接入桌面运行，也不表示完整 N 插件已兼容。

## AI 模组制作器 · 1.0-preview

**模组制作**以项目库为入口，按项目、分类和独立文档组织持续开发。项目库只显示名称、源码版本数量、更新时间与归档状态，支持搜索和分页；进入项目后再打开功能或源码，不会在列表中展开全部内容。

1. 点击 **新建项目**，用自然语言描述玩法、系统、规则和长期目标。提交后使用 AI 管理中已保存并选中的预设，自动启动共享 Pi 引擎；没有独立的登录或密钥设置。
2. 在 **AI 任务** 查看回复、修改建议和源码产物。AI 可能说明缺少的信息或未支持的实现；没有源码产物时不能登记源码项目。产生源码后填写版本说明，登记为持久项目。
3. 项目工作区提供可折叠导航、面包屑和文档标签页。**物品、方块、规则、系统、资源、其他**各自打开功能摘要列表；点击一项才打开完整需求文档。文档可记录自然语言需求、人工开发状态和相关源码路径，不使用固定物品属性表格。
4. 在右侧 **AI 协作**描述修改要求。当前功能文档和相关路径会作为上下文，宿主核对所选的已登记源码版本，并带上已保存项目说明。模型可提出复杂 Java 与资源修改；用户审阅后才产生新副本。
5. **源码**提供分页资源树、文件标签、分段只读浏览、字面文本搜索和受支持文件的草稿编辑。进入编辑前显式读取有界编辑快照，预览差异并确认后创建副本。**版本与差异**负责选择续作基础和比较历史版本；**项目设置**负责名称、目标和归档。

功能文档持久保存在项目工作区记录中，与源码版本、手写保护和 AI 权限分开。分类列表每页最多 50 项，每项目最多 4096 个功能文档，工作区记录总计最多 1 MB；单文档需求最多 6000 字符、最多 32 个相关路径。人工标记“已完成”只表示开发者填写的进度；相关路径不授予读取或修改权限。项目文档变动与功能文档变动分别核对 revision，拒绝过期保存并保留本地草稿，刷新后可明确采用最新 revision 重试。

未提交的项目说明、功能文档、AI 输入和源码草稿在当前启动器会话中保留，进入 AI 管理或切换文档不会覆盖它们；重启后只有保存到宿主的文档仍在。源码缓存最多 32 个文件、总计 2 MB。AI 使用已登记版本，不包含尚未审阅提交的源码草稿；新产物必须先登记，再从它继续开发。尚未登记的新建任务与续作任务关联保留在当前界面会话，重启后可通过“登记已有源码”选择其任务产物。

手写修改会自动保护，也可以单独保护文件。更新模板会保留受保护内容；同一任务包含多个源码产物时，可在任务页选择当前与历史副本，审阅后创建恢复副本，原工程仍保留。可从界面打开工程目录，继续使用自己的编辑器和构建工具。

普通模板修订和源码编辑后的模板更新使用同一套文件保护检查，每次创建副本都会更新保护记录。预览会列出保留的受保护文件和未应用的模板变更；相关源码与新资源是否一致仍需自行核对。删除或改名物品、恢复较早副本时，预览会提示被移除的物品 ID；源码恢复不会恢复游戏存档。

自动保护适用于制作器中经过预览确认的修改。模板文件或受保护文件若被外部编辑器改动，制作器会拒绝不一致的模板或保护记录，保留原文件；当前不支持自动导入这些外部修改。可以继续在外部编辑器中维护，也可以在未改动的历史副本上重新提交源码修改。

底层的初始工程模板支持普通物品、贴图和配方，最多 16 个物品；界面不提供静态模板生成入口，AI 可以调用它建立 Fabric 1.21.1 工程。功能文档数量不受这个模板物品数量限制，也不自动转换成模板物品。复杂玩法不受模板字段表达能力的限制：源码编辑可修改已有 Java 与受支持的资源文本，AI 续作还可提出新增 Java 类和资源文本，但具体 API、入口注册和行为正确性仍需开发者核对。构建脚本、保护元数据和二进制资源不能通过文本补丁修改。生成源码不代表已成功编译或能在游戏中运行；启动器不会自动执行工程构建脚本。

### 项目与源码版本

在 **模组制作 → 登记已有源码** 选择已结束任务的源码产物，填写项目名称、项目说明和版本说明，即可保存项目。可以登记制作器工程或搬运器产生的文本副本，随后追加版本、选择历史版本、编辑说明或归档项目。归档可以撤销，不会删除源码。项目版本保存产物引用和内容指纹，不会移动或改写原工程；任务目录与记录需一并保留。

项目说明适合记录玩法要求、设计决定和手写内容的约束。切换项目或进入 AI 管理时，未保存的说明保留在当前启动器会话中；重启后只有已保存的说明仍在。保存时若项目已变化，会拒绝覆盖并保留草稿，刷新后可明确选择用当前草稿覆盖最新说明。

在 **版本与差异**选择制作器历史版本，可浏览它的源码或以它为基础继续开发。搬运版本在同一工作区只读查看；继续迁移应使用搬运器项目的原有处理流程。**AI 协作**使用 AI 管理中已经保存并选中的预设，复制所选制作器版本到新任务，将项目说明、需求和源码清单交给共享 Pi 引擎。模型可读取现有源码、提出复杂 Java 与资源修改，由用户审阅后生成新副本。续作不会替换旧版本，也不会自动将结果登记为项目版本；在任务产物上点击“登记源码版本”保存新的版本。

项目最多 128 个，每项目最多 128 个源码版本；项目说明最多 8192 字符。编辑与 AI 续作快照沿用共享审阅限制（最多 300 个文件、总计 256 KB），尚不支持任意规模的外部工程导入；IDE 页面分层不扩大底层编辑和续作限额。源码文件若被外部改动或缺失，续作会拒绝使用不一致的版本。

项目页的 **源码浏览** 可以按文件路径筛选、分页查看文件清单，并分段读取 UTF-8 编码的 Java、JSON、语言、Markdown、属性、Gradle、Kotlin 脚本、TOML 与 XML 文本。可使用区分大小写的字面文本检索，结果显示文件与行号；不是正则或语义搜索。返回的每页和片段都属于所选版本，不会编辑源码。

只读索引支持最多 1024 个文件、总计 8 MB、每文件最多 1 MB。建立索引时流式核对原产物清单与哈希，不在内存中复制整个工程。文件列表每页最多 50 项，文本片段最多 16 KiB；检索每页最多扫描 32 个文本文件或 2 MB，最多列出 40 条匹配，达到上限会显示截断说明。点击匹配项从文件开头分段查看，行号供定位参考。未列入产物清单的文件、链接、缺失或修改后的内容会拒绝读取。

超过编辑快照限制的已登记产物可以浏览和检索，但不会因此获得源码修改或 AI 续作权限。索引目前是只读浏览能力，不是外部工程导入器，也不会自动把整个工程发送给模型；模型调用仍使用既有的有界续作快照。项目记录格式保持不变。

同一项目登记至少两个源码版本后，可以在 **比较源码版本** 选择基准和目标版本，按“基准 → 目标”的方向查看新增、删除、修改与未变文件的数量。变化清单支持路径筛选，每页最多 50 项；按路径与内容哈希比较，改名会表现为删除和新增。每次比较都重新核对项目 revision、两个已登记版本的指纹与产物清单；源码被外部修改、缺失或包含链接时会拒绝比较。

选择变化文件，再点击 **查看文本预览**，可以查看 UTF-8 文本的新增、删除与保留行及两侧行号。每侧最多显示开头 16 KiB、200 行，比较结果最多 400 行；达到字节或行数上限会明确显示截断，后续变化不在该预览中。二进制、不支持的文件类型或无效 UTF-8 仅显示不能文本比较的原因，仍保留文件变化状态。可到源码浏览中分段查看受支持文本的后续内容。

比较只用于查看，不修改源码、基准版本、手写保护或 AI 权限，也不产生补丁、调用模型、编译模组或启动游戏。两侧各自沿用只读索引的文件和容量限制；可比较制作器与搬运器登记在同一项目中的产物。

界面分别显示源码版本已登记、模组编译未运行、游戏验证未运行。当前不支持启动测试游戏、模组组合测试、通用完整移植或从插件直接执行源码修改；搬运产物可以统一管理，但 AI 续作目前只接受制作器工程。

## 模组搬运器 · 0.6.0

**一键搬运**页面以搬运管理为入口，保存项目、讨论、每轮处理记录和历史文本副本。输出一次后仍可继续维护；任务结束不表示模组已经完成搬运或通过游戏验证。

1. 在模组下载详情中选好版本，点击「创建搬运项目」；也可在搬运管理中新建项目，填写 Modrinth、CurseForge 或 MC 百科的模组项目链接。
2. 填写项目名称、搬运目标和要求。Modrinth 链接可读取项目身份、许可证与作者提供的源码入口；指定版本还会核对它所属的项目。CurseForge 和 MC 百科目前仅关联链接资料，不获取它们的文件。可从搬运管理返回模组下载页继续选择。
3. 导入与所选版本对应的**本地源码目录**，选择目标版本，声明源码修改权限；测试版目标需要接受测试版状态。没有源码时，可以先建立项目并保留需求。
4. 明确选择允许补丁修改的文件，使用静态分析或共享 AI 预设开始本轮处理。查看风险、源码证据、未验证依赖和迁移计划。
5. 查看受支持配方或手动文本修改的补丁预览，核对未支持事项与验证限制，再确认创建导入文本的新副本。

链接输入目前接受直接的 HTTPS 地址：Modrinth `/mod/<ID 或普通 slug>`（可带 `/version/<版本 ID>`）、CurseForge `/minecraft/mc-mods/<slug>`（可带 `/files/<文件 ID>`）与 MC 百科 `/class/<数字 ID>.html`。普通 slug 限字母、数字、下划线和连字符；带查询参数、片段、凭据或转义路径的地址不支持，请先整理成项目地址。

在项目讨论中持续补充需求、意见、BUG、日志和测试反馈。运行中补充的内容保存给后续轮次，正在运行的任务保留提交时的输入。真实 AI 可提出问题，记录本轮已处理、尚未处理和限制；提问后结束本轮，不占用引擎等待名额。保存答复后，点击「开始下一轮处理」继续。AI 的说明仍需核对，不能代替编译或运行验证。用户可标记需求与 BUG 已解决，也可重新打开。

每轮使用当时的源码基础、目标、讨论与文件授权。项目配置可在本轮结束后修改；旧任务与补丁继续保留原来的输入。历史副本可以明确选作下一轮源码基础，旧副本仍保留。归档项目保留全部记录，可恢复后继续。既有的独立任务仍可查看。

在「历史源码差异」选择同一项目两个已登记版本，点击「查看差异」，可比较处理轮次的冻结输入与历史文本副本，查看新增、删除、修改文件与有界文本差异。默认比较较新轮次最后登记的副本与该轮冻结输入；也可选择不同轮次或两个副本。读取时重新核对源码指纹、批准记录和整个副本的文件清单，损坏或外部改动会报错并保留原记录；部分旧冻结输入缺少可核对指纹时不能比较。此操作只读，不修改基础、不创建或应用补丁，也不自动合并变化。

每个比较版本限制在现有约 30 KB、最多 300 个文本文件的范围内；不比较二进制或未导入文件。列表保留全部冻结输入和容量范围内较新轮次的副本，最多 256 个版本，省略数量会显示。每文件差异最多约 6 KB，总差异文本最多约 48 KB；大文本块可能改用整块删除与新增，超限会明确提示，文件分类与指纹仍完整。

当前内置转换方案包括：Fabric 的 5 个身份与展示字段映射到**已有** NeoForge 元数据模板，以及限定的 Fabric/Yarn **1.20.6 → 1.21 Identifier** API 改写。Identifier 配方还要求明确声明源码配置，并导入 `gradle.properties` 中字面固定为 1.20.6 的 `minecraft_version` 或 `minecraftVersion`。只改写能确认类型、参数为直接字符串字面量的构造调用；歧义、动态参数、缺少模板、版本冲突和其他未支持事项保留说明。配方诊断与补丁内容一起绑定确认摘要。元数据修改不意味着入口、依赖和游戏行为已经完成迁移。

不支持直接转换 JAR，也不是通用一键搬运。目标目录来自离线快照，不是完整兼容性目录。不会自动下载或执行仓库源码，不自动构建或启动游戏。补丁副本只包含明确导入的文本，不复制被跳过的二进制资源。重新导入上游源码会替换后续处理的基础，**目前不自动合并上游更新与手写修改**，请先自行核对差异。

共享引擎接受约 30 KB 的导入文本快照，最多 300 个文件；超限会拒绝导入或处理。项目记录支持最多 128 个项目、每项目 64 轮和 256 条讨论，单项目记录上限约 800 KB。AI 上下文保留项目目标、未解决需求与 BUG，以及容量范围内的近期讨论；未包含的旧讨论仍保存在项目中。未解决事项超过上下文额度时，需先整理或标记已解决事项。项目保存在 `.pcl-rust/experimental/porter-projects/`；损坏、未来格式和检测到的外部改动会保留记录并拒绝覆盖。关闭启动器会停止活动任务；重开后保留项目与结果，未完成轮次显示中断，需要手动开始新轮次。

## 共享 Pi Agent 引擎 · v7

制作器与搬运器共用本地任务引擎，支持两个独立任务同时运行。工程副本和任务记录保存在项目的 `.pcl-rust/experimental/`，关闭启动器时会停止活动任务。

模组制作界面直接使用 AI；搬运器仍可选择静态分析。在 **工具 → AI 管理** 选择提供商和模型、填写 API Key、预设名称并点击「保存预设」，再提交制作需求或在搬运器选择真实 AI 方式；调用时自动启动，也可在 AI 管理页点击「启动」。此页面配置的是两个工具共用的引擎，不是独立聊天窗口。

内置提供商来自随包固定的 Pi 模型目录，包括 OpenAI、Anthropic、DeepSeek、OpenRouter、Groq、Mistral 等 API Key 提供商。不是 DeepSeek 专用引擎；列表不在线刷新，模型是否开放以及账号权限由提供商决定。当前使用 API Key，不导入 Pi CLI 的登录凭据；OAuth、云账号认证和 Google 原生协议尚未接入。

选择「自定义提供商」可填写模型 ID、基础地址和上下文窗口，支持 OpenAI Chat Completions、OpenAI Responses 或 Anthropic Messages 协议，也可连接本地 HTTP 服务。基础地址不含具体请求路径：OpenAI 兼容服务通常使用 `https://example.com/v1`，Anthropic 兼容服务通常使用 `https://example.com`。无须认证的本地接口可留空密钥；需要认证的接口应填写对应密钥。自定义模型默认不启用推理专用参数。选择新的提供商会清空密钥输入；编辑同一预设且未改变提供商或接口时，留空可保留已保存密钥。

预设保存提供商、模型、思考强度、密钥与高级限制，可新建、切换、修改和删除。密钥输入使用密码遮罩；密钥保存在本地私有文件 `.pcl-rust/experimental/ai-presets.json`（权限 0600），不会返回到界面或进入任务记录。停止引擎会取消活动 AI 任务，保留预设；重开启动器后预设仍在。运行中的任务保留提交时的配置，预设修改用于后续任务。

「高级设置」默认折叠，可调整每个预设的模型调用次数、工具调用次数、时长、输出量和估算费用。默认每任务 32 次模型调用、128 次工具调用、15 分钟，单次输出最多 8192 tokens；模型自身的输出上限仍生效。有目录价格或填写自定义价格时，默认使用 $5 的估算额度；未填写自定义价格时不执行费用估算限制，其余限制仍生效。估算不是实际账单。真实 AI 服务尚未进行在线验证，调用可能产生接口费用；模型输出需自行核对。模型不能替用户批准补丁，也不会获得游戏目录写入权限。

实验功能需要 **Node.js 22.19+、Python 3.11+**。`build-native.sh` 会按锁文件安装 Pi 依赖；Pi SDK 固定为 `1.0.4`。
